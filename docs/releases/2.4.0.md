# landspec 2.4.0

## Every PR gets the independent review, at every level

Task and spec PRs were already reviewed at every level. Any other PR (a small fix, a dependency
bump, landspec's own setup or level change) opened with no review. Now:

- `pr.sh fix "<title>" <body-file>` opens any PR that is not a task with the same gate as a task
  PR: a recorded `ready` review for the exact diff, a `## Review` section, the test command,
  mutation testing and the security scan. It needs no issue and no feature, and it refuses on a
  base branch.
- The guard blocks a raw `gh pr create` and points to `pr.sh`. A promotion whose head is a
  long-lived branch (`develop` into `main`) still opens directly, since each PR in it was reviewed.
  People are not affected: the guard only checks the commands Claude runs.
- `/landspec:init` and `/landspec:level` open their setup PRs through `pr.sh fix`, with a review.

## A sharper plan review (#108)

- Non-markdown files in the spec folder (measurement scripts, fixtures) are reviewed as code, and a
  `research.md` claim that rests on a script hiding an error is a finding.
- Each state machine (in `data-model.md`, or `plan.md` when there is none) is checked against one
  stated invariant: out of order, delivered twice, replayed, opposite actions both pending.
- When a fix round raises a finding of a class an earlier round raised (ordering, race,
  idempotency, …), the author states the invariant and runs one full round that still gets the
  earlier findings, instead of patching one case at a time. Once per class.

## Spec PRs (#115, #116)

- Running `pr.sh spec` again rewrites the open spec PR's body, so a task issue added later shows
  in it. Hand edits to that body on GitHub are replaced, and the run says so.
- A later commit says "update" instead of "add". `pr.sh spec "<title>"` takes a title in the
  language your project's rules ask for; it names the commit and a new PR.

## Fixes

- **Guard (#103):** a `cd` inside `sh -c`, in a pipeline stage or before a lone `&` no longer
  moves the guard, so the commands after it are still checked where they run.
- **Guard (#104):** `--git-dir`, `--work-tree`, `GIT_DIR=` and `GIT_WORK_TREE=` are followed: the
  guard checks the repository git writes to, not the current folder's. A redirection glued to a
  word (`--no-verify>/dev/null`) now ends the word, as in bash.
- **Guard:** a value-taking option at the very end (`git -C`, `gh pr create -H`, `gh -R`) no
  longer loops until the hook times out.
- **next (#105):** when origin's branches or the open PRs cannot be read, or the fetch fails,
  `next` stops and names the reason, instead of offering a task another clone claimed, or exiting
  silently.
- **issues (#107):** nested lists and blank lines under a task's Impact or Completed when reach the
  issue body, and `issues.sh --sync` repairs issues that were cut short.

## Dependencies

- trivy 0.76.0 → 0.76.1 in `pins.sh` (#95). osv-scanner and semgrep stay put until their newest
  release has been out for 14 days.
- pnpm/action-setup 6.1.0 → 6.1.1 in the pinned workflows and `pins.sh` (#100).

## Upgrading

`claude plugin marketplace update landspec && claude plugin update landspec@landspec`, then
restart Claude Code. Then run `/landspec:init` in each project, so its copy of the scripts gets
these fixes and `pr.sh` gets the `fix` mode. Until then, nothing changes there: the guard blocks
`gh pr create` only once the project's `pr.sh` can open a small fix.

The first `issues.sh --sync` after upgrading rewrites, once, every open issue whose task has a
wrapped field, since line breaks are now kept.
