# landspec 2.0.0

jit-speckit is now **landspec**: specs land as merged PRs. Nothing else changes in how it works.
The repository, the plugin, the commands and the files in your project all take the new name.

## Upgrading

1. Install the new plugin and drop the old one:
   `claude plugin marketplace add iamalisson/landspec`, then
   `claude plugin install landspec@landspec`, then
   `claude plugin uninstall jit-speckit@jit-speckit` and
   `claude plugin marketplace remove jit-speckit`.
2. Run `/reload-plugins`, then `/landspec:init` once in each project. It prints
   `renamed: jit-speckit is now landspec`, moves your level and settings to
   `.specify/extensions/landspec/landspec-config.yml`, and moves the constitution block, the file
   record and your git hook lines. Commit the result.

- Until that init, `/landspec:remove` refuses, and the git guard still runs but does not read the
  old settings, so a custom `base_branch` or `level: lite` is ignored. Run init first.
- Reviews recorded before the upgrade need a new run, because the records moved. On `full`, so does
  `/speckit-analyze`, for the same reason.
- A secret line marked `jit:allow-secret` stays allowed; new ones use `landspec:allow-secret`.

## What changed name

| Was | Now |
|---|---|
| `/jit-speckit:<command>` | `/landspec:<command>` |
| `/speckit-jit-<command>` | `/speckit-landspec-<command>` |
| `.specify/extensions/jit/`, `jit-config.yml` | `.specify/extensions/landspec/`, `landspec-config.yml` |
| `.specify/jit-files.sha256` | `.specify/landspec-files.sha256` |
| `<!-- jit:start -->` in the constitution | `<!-- landspec:start -->` |
| `jit: ...` messages | `landspec: ...` messages |
