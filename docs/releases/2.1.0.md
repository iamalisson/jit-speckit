# landspec 2.1.0

Tasks are now planned so that each one is safe to reach production on its own. Other people
promote the base branch while a feature is half built, so a task that adds a visible screen before
the rest of the feature is done ships an empty screen to users.

## What changed

- **`/speckit-tasks`**: a feature users can see ships dark. The first task that adds something
  visible (a screen, route, menu entry, an endpoint other clients call) puts it behind a flag that
  is off by default, and the feature's **last task** turns the flag on, depending on every other
  task. A migration stays backward compatible with the code already in production.
- **Plan review**: a task that makes the feature visible before its last task, a feature with no
  task that turns the flag on, or a migration the production code can't run against is a finding,
  before any issue is created.

## Upgrading

Update the plugin, run `/reload-plugins`, then `/landspec:init` in each project and commit the
result. Features whose tasks already exist keep them: edit their tasks by hand if one exposes the
feature early.
