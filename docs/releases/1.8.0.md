# landspec 1.8.0

1.8.0 fixes what the critical-points review of 1.7.2 found (feature 001,
[`report.md`](../../specs/001-critical-points-review/report.md)): every public High and Medium
finding, plus #41. It also makes the review one fast pass on the diff that still goes deep where
the risk is. Each fix came with a check that was seen failing before the change, and the whole release
was run end to end on a real repository
([`sandbox-run.md`](../../specs/002-review-fixes/sandbox-run.md)).

## Upgrading

- **Update the plugin first.** Plugins don't update themselves:
  `claude plugin marketplace update landspec && claude plugin update landspec@landspec`.
- **Claude Code 2.1.295 or later.** Below it, a guard that times out or crashes lets the command
  through (F2.4).
- **Refresh each project:** run `/reload-plugins`, then `/landspec:init` in the project. A
  plugin copy older than the project now refuses to set it up (F5.4).
- **Files with the "managed file" line are re-created by that refresh** (F5.2, F4.7, F5.3). Commit
  your edits to them first, or delete the line to keep the file as it is. A workflow that has no
  "managed file" line is never replaced. To get the current `security.yml` (Semgrep on `full`)
  or `close-linked-issues.yml`, delete the file and run `/landspec:level <level>` again.
- **The review is one fast pass.** Reviews run on Sonnet by default (`review_model: opus` or `fable`
  in `landspec-config.yml`). Only a real bug in the changed lines blocks; test gaps and Lows go in the PR
  body. It needs no Copilot subscription, and `pr.sh` no longer requests a Copilot review.
- **A review recorded before this release needs a new one**, because the diff id changed (T014).
  `pr.sh spec` also stops on a stale plan review: run the plan review again after changing
  `tasks.md`.
