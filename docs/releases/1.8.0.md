# jit-speckit 1.8.0

1.8.0 fixes what the critical-points review of 1.7.2 found (feature 001,
[`report.md`](../../specs/001-critical-points-review/report.md)): every public High and Medium
finding, plus #41. It also makes the review go deep where the risk is and stay cheap on fix
rounds. Each fix came with a check that was seen failing before the change, and the whole release
was run end to end on a real repository
([`sandbox-run.md`](../../specs/002-review-fixes/sandbox-run.md)).

## Upgrading

- **Claude Code 2.1.295 or later.** Below it, a guard that times out or crashes lets the command
  through (F2.4).
- **Refresh each project:** run `/reload-plugins`, then `/jit-speckit:init` in the project. A
  plugin copy older than the project now refuses to set it up (F5.4).
- **Files jit-speckit wrote are kept when you changed them** (F5.2, F4.7, F5.3). A workflow that has
  no "managed file" line is never replaced. To get the current `security.yml` (Semgrep on `full`)
  or `close-linked-issues.yml`, delete the file and run `/jit-speckit:level <level>` again.
- **The review runs on a strong model.** Reviews now run on Opus by default
  (`review_model: sonnet` or `fable` in `jit-config.yml`). A session on a cheaper model pays more
  for reviews.
