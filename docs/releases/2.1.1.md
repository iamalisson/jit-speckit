# landspec 2.1.1

A fix to the git guard, the hook that checks the git commands Claude runs.

## What changed

- **The guard checks each git command in the repository it runs in.** It follows `cd`/`pushd`
  through the command and `git -C`. Before, it judged every command by the repository the Claude
  Code session started in:
  - a commit into another repository (`cd ../app && git commit`, `git -C ../app commit`) was
    refused with "committing on 'main' is not allowed" whenever the session's own repository was
    on `main`;
  - from a session outside a landspec project, `cd <landspec repo> && git commit` on a protected
    branch was not checked at all.
- A repository without landspec is left alone. A `cd` the guard cannot resolve (`cd $X`, `cd -`)
  is checked against the session's repository, as before.

## Upgrading

`claude plugin marketplace update landspec && claude plugin update landspec@landspec`, then restart
Claude Code. The guard runs from the plugin, so no `/landspec:init` is needed for this fix.
