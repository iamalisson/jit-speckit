# landspec 2.3.0

## New: `/landspec:report`

When landspec gets something wrong in your project (a script that fails or refuses wrongly, a
generated file that is wrong, a step that is missing or confusing), run `/landspec:report`. It
drafts an issue for the landspec repository from what just happened:

- the facts, not guesses: the plugin and project versions, the level, the `specify` and `gh`
  versions, the exact message, and the landspec file and line it comes from;
- nothing private from your project: secrets, internal URLs, customer data and private
  organization or repository names are replaced with neutral stand-ins, and the reproduction is a
  minimal setup anyone could recreate;
- duplicates first: it searches the existing issues and offers to add a comment instead;
- filed only after you say yes, since the issue is public. If `gh` cannot file it, you get the
  draft and the new-issue link.

## Docs

- The README's Install section now says that `/plugin install` is the whole install and that
  `/landspec:init` sets up spec-kit (don't run `specify init` yourself). It lists the tools your
  machine needs, `uv` included.

## Upgrading

`claude plugin marketplace update landspec && claude plugin update landspec@landspec`, then
restart Claude Code. `/landspec:report` comes with the plugin: no `/landspec:init` is needed for it.
