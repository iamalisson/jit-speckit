# landspec 2.2.0

Two real runs found what landspec's reviews let through, and an outside reviewer (Copilot) caught
in minutes. Both came from the same root: the reviewer only looks for what its method lists. This
release adds the missing checks.

## A task's inputs and commands

On one spec PR, four plan reviews passed a task that read a file that existed only untracked on the
author's machine. Whoever started the task from a clean clone had nothing to read. The same task's
`gh pr view <n>` had no `--repo`, so run from another clone it read another project's PR.

- **Plan review and the author's grounding step:** every file, data set, URL or credential a task
  reads is on the base branch, in the spec folder, or written in the task. A file that exists only
  in the author's tree is a finding. Commands in *Completed when* run from any clone and directory
  (`gh --repo`, paths from the repository root).
- **`pr.sh spec` refuses** a `tasks.md` that names (in backticks) a file git does not track, before
  any branch switch. When local changes block the switch, it says to commit or stash them.
- **Review rounds converge:** the author passes the last round's report and an answer to each
  finding. A finding keeps its severity unless the text changed or there is a new fact.
- **The reviewer writes its own report file** and returns `Report file: <path>`. The author records
  that file instead of retyping it.
- **The size rule** (about 400 lines per task) no longer counts generated files, lockfiles, or
  markup and data copied as is.

## Accessibility

On a task PR, footer links at 2.97:1 contrast (WCAG AA needs 4.5:1) passed the branch review and
the fix round. Nothing in the chain looked at accessibility, the reviewer's "no style" rule covered
CSS colours, and the colour came from an existing page that already failed.

- **Constitution, every level:** a new *Accessibility* section for projects with a user interface
  (WCAG 2.2 AA: text at least 4.5:1, large text and icons 3:1, visible focus, accessible names).
- **Reviewer:** an interface some people cannot use is a bug, at least **Medium**, with the
  computed contrast as evidence. Accessibility is not style, and matching an existing page is no
  defense: a copied defect is still a defect.
- **Tasks template:** a task that changes what people see names its accessibility check in
  *Completed when*.
- **`review.sh risk`:** a new `RISK=ui` for stylesheets and markup templates, so the reviewer reads
  them closely instead of seeing `RISK=none`.

## Also

- **`issues.sh --sync`** rewrites the body of each open issue from its task's current sub-bullets,
  after a fix to tasks that already have issues. Closed issues are left alone. Edits made to the
  issue on GitHub are lost.
- **Git guard:** `git config core.hooksPath` with no value is a read and is allowed; setting or
  unsetting it is still blocked.
- **`/landspec:init`** says when the setup created `.claude/settings.json` with the `attribution`
  block, and how to keep attribution.

## Upgrading

`claude plugin marketplace update landspec && claude plugin update landspec@landspec`, restart
Claude Code, then run `/landspec:init` in each project and commit the result: the new constitution
section, tasks template and review method come with it. Tasks written before the upgrade keep
their old text.
